# 產品領料單系統

示範用的產品領料單網頁：請領部門申請 → 主管審核 → 倉管發料。所有資料皆為虛構。

- 網站：https://chc6487-byte.github.io/repair-system/
- 需求筆記：[產品領料單/需求筆記.txt](產品領料單/需求筆記.txt)
- 欄位規格與範例資料：[產品領料單/領料單欄位表.xlsx](產品領料單/領料單欄位表.xlsx)
- 資料庫建表 SQL：[supabase/picking_schema.sql](supabase/picking_schema.sql)
- 網頁可安裝成 App（PWA）：用手機瀏覽器開啟網站後，選「加入主畫面」或「安裝應用程式」。

## 上線步驟

1. 在 Supabase SQL Editor 執行 `supabase/picking_schema.sql`。
2. Supabase 後台 → Authentication → Sign In / Providers：開啟「Allow anonymous sign-ins」
   （「Allow new users to sign up」也要保持開啟）。
3. 儲存庫設為公開，並在 Settings → Pages 選擇 `main` 分支、根目錄發佈。

## 進入系統（不需帳號密碼）

開啟網站後，從「選擇人員」下拉選單選人（自動帶入部門與角色），或選「其他（自行填寫）」再填寫名稱、部門與角色（請領／主管／倉管），按「進入」即可使用（Supabase 匿名登入）。

下拉選單的名單寫在 `app.js` 的 `PRESET_USERS`，目前有：

| 名稱 | 部門 | 角色 |
|---|---|---|
| 陳慧真 | 倉管課 | 主管 |

- 登入狀態只存在這台裝置的這個瀏覽器；登出、清除瀏覽器資料或換裝置後會變成新的使用者，原本的身分無法找回。
- 名稱、部門與角色進入後無法自行修改；要換角色就登出後重新進入。管理員也可依 `supabase/picking_schema.sql` 檔案最後的範例用 SQL 修改。
- 已送出的領料單會保留，不受登出影響。

> 注意：不需驗證身分且角色由使用者自行選擇，任何人都能以主管或倉管身分操作，只適合示範使用。

## 功能切換

登入後，頁面上方有「功能」下拉選單：

| 選項 | 顯示內容 |
|---|---|
| 領料 | 新增領料單（只有請領部門）＋全部領料單 |
| 審核 | 待審核的領料單 |
| 發料 | 待發料的領料單 |

預設依角色開啟：請領→領料、主管→審核、倉管→發料。實際能按的按鈕仍依角色決定。

## 角色與權限

| 角色 | 可以做的事 |
|---|---|
| 請領 | 新增領料單；修改自己部門、尚未審核通過的單 |
| 主管 | 審核通過自己部門的單 |
| 倉管 | 對已審核通過的單勾選發料 |
| 所有已設定的帳號 | 查看所有部門的領料單 |

前端只使用 publishable key；secret key 不可寫進任何檔案。
